## 1. Files (paths inside the ramdisk = `recovery/root/` of the device tree)
| file | purpose |
|---|---|
| `system/bin/qseecomd` | Qualcomm TEE daemon (RPMB + SSD listeners, loads helper libraries with dlopen) |
| `system/bin/android.hardware.keymaster@4.x-service-qti` | Keymaster HAL (version as in the ROM's vendor manifest) |
| `system/bin/android.hardware.gatekeeper@1.0-service-qti` | Gatekeeper HAL; its `-impl-qti.so` goes to `vendor/lib64/hw/` |
| `system/bin/keystore2` (+ its libraries) | from the OrangeFox/TWRP build, not from the ROM |
| `vendor/lib64/*.so` | vendor libraries of the closure: `libQSEEComAPI`, `librpmb`, `libssd`, `libdrmfs`, `libdrmtime`, `libGPreqcancel(_svc)`, `libqisl`, `libkeymasterdeviceutils`, `libkeymasterutils`, `libqtikeymaster4`, `libqcbor`, `libdiag`, `libtime_genoff` ... |
| `system/lib64/*.so` | AOSP libraries (libc, libhidlbase, libutils, libcrypto, `android.hardware.keymaster@x.y.so` ...): produced by the recovery build; `libion.so` and `libxml2.so` are added through `TARGET_RECOVERY_DEVICE_MODULES` |
| `system/etc/vintf/manifest.xml` | **framework manifest** (mandatory, `assets/vintf/framework_manifest.xml`) |
| `vendor/etc/vintf/manifest.xml` | device manifest listing the HALs whose binaries are in the ramdisk |
| `init.recovery.<hw>.rc` | firmware mount, symlink of by-name, diagnostics (`assets/init.recovery.HARDWARE.rc.in`) |
| `init.recovery.qcom_decrypt.rc`, `...fbe.rc` | generated by the build from `device/qcom/twrp-common` (services and triggers) |
| `ueventd.<hw>.rc` | permissions of `/dev/qseecom`, `/dev/ion`, `/dev/sg*`; copy from a reference tree |
| `system/etc/recovery.fstab`, `twrp.flags` | `/data` line with the crypto flags, `/metadata`, `/firmware` |
| `system/bin/fox_decrypt_diag.sh` | decrypt-chain diagnostics |

## 2. Where the blobs come from
Take them from the **same ROM build whose firmware is on the phone**: vendor libraries and the trusted app in the modem partition have to match.
* `scripts/collect_decrypt_blobs.py --adb --out <tree>/recovery/root` pulls from `/vendor` of the running phone (shell user can read `/vendor` on stock-like ROMs);
* `--vendor-root <dir>` for a mounted `vendor.img` (erofs: `mount -t erofs` or `fsck.erofs --extract=<dir> vendor.img`; ext4: loop mount; `payload.bin` of an OTA zip: `payload-dumper-go -p vendor`), or the `proprietary/vendor` tree of a blob repository (verified: it reproduces the reference tree byte for byte);
* the trusted app itself (`keymaste.mdt/.b0x`, `cmnlib*`) is *not* put into the ramdisk: it lives in the firmware partition and is mounted at `/vendor/firmware_mnt`.
The collector writes `port/blobs.txt` (source name + sha256 of every file): fill in the ROM name and keep it for the NOTICE.

## 3. Library closure and dlopen
`verify_ramdisk.py` walks DT_NEEDED of every decryption service (found from the init `service` stanzas) through `vendor/lib64`, `vendor/lib64/hw`, `system/lib64`, `system/lib64/hw`.
`qseecomd` loads some libraries by name with `dlopen()` (not visible in DT_NEEDED): the collector finds their names as strings and copies those present in the vendor tree, except
`libops.so`, `libsecureui.so`, `libspl.so`: qseecomd runs without them (they log `dlopen ... not found`), and `libops.so` pulls in the display stack (the first run of the closure check on the reference tree flagged it, and a stale copy of it had been shipped by two early images).
A stale library left in `out/target/product/<device>/` from an earlier build can sneak into the next image; the build script removes the staging directories, `verify_image.sh` compares the ramdisk with the tree.

## 4. init pieces
* **Firmware mount** (Qualcomm): `mount vfat /dev/block/bootdevice/by-name/modem /vendor/firmware_mnt ro nosuid nodev noexec shortname=lower,uid=1000,gid=1000,dmask=227,fmask=337` in `on fs`
  after `wait ... by-name/modem`. The Keymaster HAL (`libkeymasterdeviceutils`) loads its trusted app from that hard-coded directory.
* The common decrypt rc defines the services with `seclabel u:r:recovery:s0`, `user root`, `LD_LIBRARY_PATH /vendor/lib64:/vendor/lib:/system/lib64:/system/lib:/sbin` and starts them from property triggers;
  device specific services of the ROM (check `/vendor/etc/init/*.rc` of the running ROM) are added by copying their stanza and setting `disabled`, `oneshot`, `seclabel u:r:recovery:s0`.
* `androidboot.dynamic_partitions=true` must be on the kernel command line of a dynamic-partition device, or the prepdecrypt trigger never fires.
* Recovery runs with SELinux permissive (`androidboot.selinux=permissive`), otherwise the services above are denied.

## 5. VINTF manifests
Without `system/etc/vintf/manifest.xml` hwservicemanager logs `Cannot read /system/etc/vintf/manifest.xml` and
`getTransport: Cannot find entry android.hidl.manager@1.2::IServiceManager/default in either framework or device VINTF manifest`; libhidl then refuses to hand out the HIDL service manager
and keystore2's km_compat aborts at start-up with `Check failed: serviceManager.get() Failed to get ServiceManager` (crash loop). The official OrangeFox/TWRP trees of the same SoC family ship that file.
The device manifest must declare every HAL that registers (keymaster `4.x`, gatekeeper `1.0`; weaver where it exists), or registration is refused.

## 6. Static check
```
mkdir rd && cd rd && gzip -dc ../ramdisk | cpio -idm        # lzma -dc for an LZMA ramdisk
python3 -I <skill>/scripts/verify_ramdisk.py . --require qseecomd --require 'keymaster|keymint' --require gatekeeper \
        --dlopen libdrmfs.so --dlopen librpmb.so --dlopen libssd.so
```
Exit 0 and `OK` mean every NEEDED library is present; WARN lines list library names found as strings but absent (the three optional ones above are expected).

## 7. Licensing
`qseecomd`, the HAL services and the vendor libraries are proprietary (Qualcomm/OEM). Their init files in the tree carry a "Confidential and Proprietary" header. Publish them only when you accept the redistribution risk,
keep the provenance (`port/blobs.txt`, NOTICE), and prefer pulling them from the user's own phone. The kernel is GPL-2.0: ship or offer the source.
